# Data files

The planner's knowledge besides the player's export. Every file carries a version, and every entry names the page its numbers came from. `src/validate.ts` checks each file; the tests run those checks on every commit.

| File               | Holds                                                                         | Maintained                                  |
| ------------------ | ----------------------------------------------------------------------------- | ------------------------------------------- |
| `gamedata.json`    | Every entity's levels (cost, time, Town Hall), counts per hall, gates, merges | Generated by `pnpm gamedata:build`          |
| `magic-items.json` | Potions, books and hammers: what each acts on, how strongly, holding limit    | By hand                                     |
| `events.json`      | Dated events and their effects, confirmed or projected                        | By hand, after each Supercell season post   |
| `seasons.json`     | Items expected per month from each source, and the Gold Pass boost pace       | By hand; every count is an editable default |

## gamedata.json and its licence

`gamedata.json` is built from [ClashKing's static data](https://github.com/ClashKingInc/ClashKingAssets)
(`assets/static_data`) at the commit pinned in `tools/gamedata-build/src/source.ts`, taken on
16 November 2026, the day of the Town Hall 19 update. ClashKing's repository is licensed
GPL-3.0, so **this file is licensed GPL-3.0 too**; the licence text is in `COPYING.gamedata`.
The planner's code is separate and loads the file as data. Credit to the ClashKing team.

To take a newer snapshot: change the commit in `source.ts`, run `pnpm gamedata:build`, and
review the diff (one entity per line). `src/real.test.ts` pins hand-checked rows, so a wrong
conversion or a changed source fails the tests until the pins are updated on purpose.

What the build does, beyond renaming fields:

- Research, hero and pet costs shift one level: ClashKing lists the price of the next level on
  each row; here a row is the price of reaching it.
- Counts per hall sum the Town Hall's unlock lists, minus the sources merged buildings consume
  (two level 21 Archer Towers per Multi-Archer Tower, and so on). These counts match three public
  Town Hall 18 exports exactly. The Eagle Artillery is consumed by the Town Hall 17 upgrade, which
  is a gate on that hall.
- B.O.B's Hut has the `extraBuilder` role: it adds a home builder but is earned in the Builder Base.
- Left out: Builder Base, super and event troops and spells (not researched), the Crafting
  Station's modules, guardians, hero equipment and supercharges.
- Squads are researched in the Laboratory like troops, unlocked by the Squad Barracks.
- ClashKing has no storage capacities, so `storage` is empty and no step waits on a storage.

`fixtures/gamedata/sample.json` stays for tests: small, hand-made, `"synthetic": true`.

## Conventions

- A level row describes **reaching** that level: the cost and time of the upgrade from the level below, and the lowest Town Hall that allows it. Level 1 of a building is its construction.
- Special buildings (Town Hall, Builder's Hut, Laboratory, Pet House, Hero Hall) carry a `role`, so code never hard-codes an id.
- The cap for an entity at a Town Hall is derived from its level rows, so it cannot disagree with them. Counts per hall are listed explicitly.
- Events with a published date are `confirmed`. Recurring entries are estimates, always `projected`, and start switched off in the app.

## Known gaps

- Snacks (Builder Bite, Study Soup) are not listed yet: their durations and holding limits still need a primary source.
- `seasons.json` has zero counts and `"status": "unset"` until the defaults are set from the last three season posts.
- The Builder Base Bonanza start and end hours assume the 08:00 UTC daily reset.
